# Contributing technical knowledge

This repository documents *Test Drive: Eve of Destruction* implementation and modding findings for humans and language models. Contributions should describe reusable mechanisms, data formats, platform differences, reproduction steps, and evidence. The repository has no personal roadmap or investigator workflow; anyone can contribute.

## Add or revise a finding

1. Identify the exact game platform and executable/build revision. PS2 `SLUS_209.10`, Xbox, the recompilation, and host platforms are separate targets. Never transfer an address, binary layout, or behavior across targets without independent evidence.
2. Prefer a focused page under `docs/<platform>/<subsystem>/` or an existing subsystem page. Use a stable descriptive filename, one clear H1 title, and relative links to related pages. Update the category metadata and index through the importer when adding a page.
3. Separate observations from interpretation and proposals. State what artifact or command supports each claim, the relevant revision, and the limits of the method. Mark unverified hypotheses plainly; do not turn an expected result into a reported result.
4. Never commit game executables, disc contents, extracted assets, generated game code, captures containing game assets, credentials, or private paths. Publish only the minimum textual evidence needed to make a claim reproducible.
5. Add citations for external claims using direct links to primary sources where possible. Include a commit/tag or access date for mutable project documentation. For local source evidence, record repository, relative path, revision, and hash via the importer; never include a personal absolute path.
6. Keep technical ownership terms precise. Words such as owner index, owner slot, object ownership, and GPU ownership describe program behavior and must not be removed as personal metadata.

## Evidence labels

Use the narrowest supported level and state it per claim:

- `static-analysis`: source, disassembly, symbols, or data inspected; no execution implied.
- `cpu-test`: synthetic or host-side test executed; identify what it exercises and does not cover.
- `integration-test`: integration path executed with named build/configuration and result.
- `live-gameplay`: rendered game behavior observed on the stated platform and revision.
- `external-reference`: supported by a cited external primary source, without implying local validation.
- `hypothesis` or `proposal`: not verified; say what evidence would resolve it.

An empty test result or an unexecuted command is not evidence. Preserve contrary observations and known gaps. The current PS2 Battle recovery page has its own maintenance path and is not regenerated by the source importer.
